## 具体布局逻辑

### 可行性检查

完成“3.3 摆放机械臂前的可行性检查/判断”，确定布局是否可行的同时，确定整个实验需要多少台导轨类机械臂和堆栈

> **结论（交付与功能拆分）**：
>
> 做成**一个纯函数 / 一个脚本** `check_feasibility(...) -> 结构化报告`，不拆成多个微脚本——因为各子判据共享同一批中间量（sumW、L_max、L_2nd、参数 a/b/c/d/e、机械臂型号的 L 与工作半径），拆开会重复计算并增加 agent 编排往返。参照现有 `feasibility.py` 的 `precheck_conflicts()` 范式：一个函数内跑多条判据，返回一个冲突/原因列表。
>
> 函数内部依次跑：① 面积检查（复用 `feasibility.py` 面积判据写法）② 算台数 n_arm/n_stack（粗估）③ 短边不等式 1/2 ④ 长边不等式 + 反解 n_max ⑤ 可达性（b<工作半径、e<工作半径）。
>
> 返回结构：`{feasible, n_arm, n_stack, n_max, mode_hint, reasons[], suggestions[]}`。agent 据此：可行就继续，不可行用 AskQuestion 让用户放宽（复用现有 skill 失败交互范式）。
>
> **可复用**：`GET /devices`（bbox/朝向）、`GET /scene/lab`（房间尺寸）、`feasibility.py` 面积判据与 `Conflict` 数据结构。
>
> **前置依赖**：需「机械臂型号 → (L, 工作半径, bbox)」对应表（如新建 `rail_arm_models.json`）。

### 布局机械臂和堆栈

#### 1. 布局第一台机械臂

参照“3.2 机械臂的摆放逻辑”中的“第一台机械臂怎么摆放”逻辑确定第一台机械臂的坐标；默认采用靠墙模式，除非用户明确说明采用居中模式——交付一个代码

#### 2. 布局剩余机械臂和堆栈

参照“3.2 机械臂的摆放逻辑”中的“后续机械臂的摆放逻辑”逻辑确定后续机械臂和堆栈的坐标——交付一个代码

> **结论（两步合并 + 默认参数）**：
>
> 1. **合并为一个函数** `place_arms_and_stacks(lab, n_arm, arm_model, params, mode="near_wall") -> {arms, stacks}`。第一台确定后，后续臂/堆栈是纯几何偏移（相邻臂中心间距固定为 `L + 2e + stack_h`，堆栈中轴线对齐臂中轴线、夹在中间、距臂 e），两步之间唯一的"决策"是第一台的靠墙/居中模式，作 `mode` 入参即可，无需在两脚本间传中间状态。
> 2. **距离参数必须有默认值**：集中定义 `DEFAULT_PARAMS`（如 a=0.5, b=0.4, c=0.2, d=0.3, e=0.4，单位 m），允许用户覆盖；其中 b、e 默认值须 < 工作半径。
>
> **关键输出**：每台机械臂必须输出**四个角坐标**，供下一阶段反推仪器坐标。
>
> **可复用**：`PlacementResult` 的 `position/rotation(theta)` 输出格式（`server.py`），保证与 `POST /scene/placements` 兼容。

### 按实验步骤顺序布置各仪器

按实验步骤顺序布置每台机械臂单侧所需要的仪器，直至全部仪器均被布置到实验室中。

> **结论（碰撞检测的必要性）**：
>
> 在本规则化布局里，仪器之间、仪器与机械臂之间**靠构造就不会碰**（有 b/c/d 固定间隙），因此碰撞检测**不再作为优化驱动**，角色降级为两类**校验守卫**：① 与环境障碍物的碰撞（用 `LabSpec.obstacles` 字段做仪器 AABB vs 障碍物）② 越墙 / 越工作半径的后置断言（长 L 仪器外端可能戳出）。这与你的判断一致。

> **结论（交付与功能拆分）**：把"选哪一侧 + 选哪些仪器 + 算坐标"**合并为一个确定性函数** `assign_and_place_instruments(arms, ordered_instruments, params) -> placements[]`，一次算出全部仪器中心坐标与朝向。
>
> 与原设想的区别：**"哪台臂哪一侧"不交给 agent 决定**——线性流程 + 从下到上 + 左先右后 下该顺序完全确定，交 LLM 只会引入不确定性，应放进脚本（按顺序生成 (臂, 侧)）。
>
> 函数内部：① 确定性的臂/侧顺序 ② 贪心装箱填满单侧（cost_w(i)=sumW_i+(i-1)c ≤ L）③ 用四角反推坐标（左侧用左下角、右侧用右上角，内边缘统一距臂 b）④ **朝向 theta**：据 `/devices` 的 `openings` 算旋转角使仪器面向导轨（左侧朝 +x、右侧朝 −x），否则前端朝向全错 ⑤ **多退少补**：删空臂；末尾仍有剩余则 n_arm+1 回上一阶段重排（删/补臂会改几何 → 仪器坐标重算，故阶段二/三由同一上层 routine 串起来）。
>
> agent 职责收敛为高层编排：拉数据 → 可行性 → 调布局 → （可选）调校验 → 推前端。
>
> **可复用**：`POST /scene/placements` 推坐标（**发两次** version bump，即原 skill 的 curl 方法）；`LabSpec.obstacles` 做环境碰撞；前端自动建设备（空场景直接推即可渲染）；`openings` 朝向字段。

落地拆分对照（agent 调用 vs 脚本）：

1. 确定当前要布置在哪个机械臂的哪一侧——**脚本（确定性，非 agent）**
2. 决定布置在这一侧的仪器是哪些——脚本（并入上面同一函数）
3. 确定这些仪器的中心坐标与朝向——脚本（并入上面同一函数）
4. 使用坐标在实验室中完成布置——原 skill 的 curl 方法（`POST /scene/placements` ×2）
5. 碰撞检测——降级为校验守卫（环境障碍物 + 越界断言）
