# 试剂最大装料量

控制台只提供一个可编辑的“最大装料量”。物态决定可用计量维度：液体默认体积，粉体使用质量。有适用额定规格时，手工最大装料量只能收紧它；缺少对应规格时，允许手工设置最大装料量。切换单位不能跳过已有约束。库存列表和试剂历史显示实际生效的最大装料量。

## 存储与默认值

复用现有 JSON 字段，不增加数据库表或列，不新增 ResourceDict 根字段：

| 位置 | 含义 | 示例 |
| --- | --- | --- |
| `resource_template.meta_data.capacity` | 领域包声明的额定容量，由 `@resource(metadata={"capacity": ...})` 同步 | `{"max_volume_ul": 100000}` |
| `material.config.capacity` | 用户设置的这一个容器的最大装料量；缺对应额定值时提供操作上限，有额定值时不能超过它 | `{"max_mass_g": 50}` |
| `reagent.meta_data.loading_limits` | 仅兼容旧记录；显式保存新的最大装料量时移除 | 不再由控制台生成 |

体积统一存 µL，质量统一存 g。旧图中 `config.max_volume` / `data.max_volume` 按 PLR 的 µL 单位读取，并作为额定约束。不从名称或尺寸猜测规格，不把化学品密度当作粉体堆积密度。

本次只修改 Uni-Lab-OS，不修改 SZLab 或其他领域包。未声明容量且旧图也未提供容量的容器仍可作为空物料存在，也可手工设置 mL 或 g 最大装料量。新增试剂、增加库存或修改容量时，必须有适用的额定上限或正有限手工上限，不能没有上限就无限制入库。手工值保存在实例配置中，不改写或伪造模板额定规格。模板同步省略容量不会删除数据库中已有的容量元数据。

固体只允许 mg/g/kg。只有 300 mL 容积规格、没有 g 规格的粉体瓶，可手工填写 50 g 最大装料量：50 g 入库成功，51 g 被拒绝；没有任何质量上限时提示手工设置。已有 `max_mass_g` 额定值仍是硬约束，不能通过手工值提高它。额定几何容积不映射粉体质量；旧手工体积限制也不能被忽略，必须显式用质量最大值替换。

液体默认允许 µL/mL/L。按质量计量或对照另一维额定约束时，必须有适用的正有限 `density_g_per_ml`，且瓶内不能声明 `concentration_value`。规则复用工作流 `convert_quantity`，避免把纯物质参考密度直接用于溶液。可换算时，对所有额定和用户上限同时进行质量/体积换算并取更严值；无法换算时拒绝，不能跳过另一维约束。例如密度明确为 1 g/mL 时，100 mL 额定容器最多对应 100 g，实际 200 g 和自定义 200 g 上限均会被拒绝。派生规格仅用于校验，不改写模板的固定规格。

没有额定规格的液体容器，可手工设置适用的体积上限；按质量设置仍须满足上述密度与浓度条件。已存的实例最大值及旧 `loading_limits` 也可提供手工上限。手工值不允许绕过已有但无法换算的另一维约束。

物态 `unknown`、`other` 或 `gas` 不能新入库；须先明确适用的固体/液体库存规则。创建使用事务内解析的目录物态、密度，编辑使用瓶内快照，目录修改不会重解释已有库存。

## 写入与兼容规则

- `container_capacity` 是录入、编辑和分装的唯一最大装料量请求字段，写入 `material.config.capacity`；可选的 `expected_material_revision` 防止覆盖并发容器修改。试剂编辑仍支持 `expected_revision`，同时修改数量和最大装料量必须在同一事务中成功。
- 空对象 `{}` 清除用户配置，恢复领域包/旧图默认值；若已有库存将因此失去所有适用上限，则拒绝本次容量修改。正有限数值才是有效上限。0、负数、NaN、Infinity、布尔值及未知键均拒绝。容量对象内某个维度为 `null` 表示该维度未配置。请求中的 `container_capacity:null` 按旧 DTO 兼容行为视为未修改。
- 同维度支持 `µL` / `μL` / `uL`、`mL`、`L` 与 `mg`、`g`、`kg`。工作流换算统一识别微升的两种 Unicode 写法。新入库拒绝未知单位；现有库存单位保持不变，不做静默换算。
- 创建物料并内联试剂、单条录入、JSON/CSV/XLSX 导入、编辑、分装均在原有事务内校验。新建数量必须大于 0；编辑允许降至 0。既有活动锁、数量预留与修订检查继续生效。任一检查失败，原子批次或分装不保留前面的试剂、数量扣减、容量设置、台账或发件箱事件。
- 旧记录保留读取和历史。保持原单位、数量不增加、浓度值/单位不变且没有改变容量或旧 `loading_limits` 时，允许减量、保持数量及修改非容量信息，包括缺少额定规格或物态未确认的旧瓶。增加数量、显式提交容量、改变旧限制或浓度则执行新校验。不会因为旧记录不满足新规则而阻止减量，也不会把兼容例外用于新入库。
- 试剂编辑省略浓度字段时保留瓶内值；显式提交成对的 `null` 才清除浓度，并按物性上下文变化执行严格校验。
- 普通数量编辑省略 `container_capacity` 时，旧 `loading_limits` 继续保留；读取时将其与容器容量取同维度较小值。`meta_data` 合并未指定的键，因此省略元数据或传 `{}` 也不会清掉旧限制、批次信息或分装来源。
- 显式提交 `container_capacity`（包括 `{}`）后，新值替换旧限制，移除该试剂的 `loading_limits`，不保留隐藏的第二个上限。其他元数据及容器配置保持不变。旧客户端仍可提交 `meta_data.loading_limits` 或分装目标 `loading_limits`；若同时提供新最大装料量，以新字段为准。
- 物料详情 `PUT /api/v1/materials/{uuid}` 显式提交 `config.capacity` 时同样替换旧限制、保留其他配置，并检查当前试剂余量。即使保存值与已有容器配置相同，也会折叠旧限制。省略 `capacity` 则保留已有设置与旧限制；`capacity:null` 或 `{}` 恢复默认值。
- 最大装料量单独变化也追加数量增量为 0 的 `reagent.adjust` 台账与事务发件箱事件，并增加试剂修订。`changes.previous.maximum_capacity` / `changes.result.maximum_capacity` 保存修改前后的实际值；清除后记录恢复的额定值，或没有上限时的 `{}`。历史保留旧 `loading_limits` / `container_capacity` 快照键以兼容老客户端。
- 分装继承源瓶的化学身份、物态、密度及密度来源、浓度和来源血缘，不重新复制后来修改的目录物性；不继承源瓶最大装料量或旧装料限制。每个目标使用自身额定规格和操作上限，按新入库规则校验；失败时源瓶也不扣减。

旧记录仅在显式保存最大装料量时转换；不会启动时批量修改库存。模板额定容量同步也不改写已有数量，后续写入按最新容量校验。本合同覆盖试剂人工库存入口；工作流动作的物理加料预检、样品与当前物质的数量结算不在本次改动范围内。

## API 示例

向只有 300 mL 容积规格、没有 g 规格的粉体容器录入时，可手工设置 50 g 最大装料量；若另有质量额定值，则该值不能低于 50 g：

```json
{
  "material_uuid": "<容器 UUID>",
  "reagent_info_uuid": "<化学品身份 UUID>",
  "quantity": 30,
  "quantity_unit": "g",
  "container_capacity": {"max_mass_g": 50},
  "expected_material_revision": 1,
  "meta_data": {"batch": "A"}
}
```

这些字段适用于 `POST /api/v1/reagents`、导入的每一行和 `PUT /api/v1/reagents/{uuid}`（编辑无需重复容器和试剂身份，可增加 `expected_revision`）。CSV/XLSX 的 `meta_data` 与 `container_capacity` 单元格使用 JSON 对象文本；导入沿用 `atomic` 参数。

`reagent.dispense` 的每个 `targets` 项支持 `container_capacity` / `expected_material_revision`。物料读取保留 `capacity`（容器有效容量）与 `rated_capacity`（领域包/旧图额定容量）。试剂读取返回 `maximum_capacity`（含尚未替换的旧限制）、`rated_capacity`、`configured_capacity`（仅用户容器上限）和 `material_revision`，同时保留原 `container_capacity` 与 `meta_data` 字段。区分额定规格与用户上限后，前端可提示固体旧瓶重新设置无法核验的手工体积限制，而不会误判仅作几何规格的额定容积；此读投影不新增数据库字段。
