# PLC / OPC UA 仿真器

:::{admonition} 阅读角色
- **业务负责人**：确认设备用途、动作名称、参数单位、成功标准和安全边界。
- **开发人员**：实现设备合同、连接方式、启动图节点、模拟能力和测试。
- **验收人员**：验证参数越界、断线、超时、联锁、未知结果和真机恢复。
:::

PLC 仿真器只在用户设备包明确声明需要 PLC 或 OPC UA 通信时使用。它用于在没有真实产线的情况下验证连接、点位映射、握手顺序、超时和故障处理，不能代替真机安全验收。

## 设备包必须交付的内容

| 内容 | 说明 |
| --- | --- |
| 仿真器名称与版本 | 安装人员必须能确认使用的是哪一版程序 |
| 启动与停止方式 | 包括工作目录、命令和正常退出方法 |
| 点位表 | 变量名、数据类型、读写方向、初始值和业务含义 |
| OPC UA 配置 | Endpoint、Namespace URI 或 Index、安全策略和证书要求 |
| 握手规则 | 命令、接受、执行、完成、复位、故障和超时的状态变化 |
| 启动图（Graph JSON）对照表 | 每个设备实例应连接哪个端点，使用哪组点位 |
| 健康检查 | 如何判断进程、协议服务和 Uni-Lab OS 客户端分别就绪 |

缺少其中任何一项时，只能完成系统安装，不能声称 PLC 联调已经完成。

## 启动顺序

1. 选择设备包提供的模拟配置，确认没有生产 PLC 地址。
2. 启动 OPC UA Server，检查监听地址和命名空间。
3. 如果设备包需要握手代理，等待 Server 就绪后再启动代理。
4. 启动 Uni-Lab OS，使 启动图 中的 PLC 节点建立会话。
5. 打开 Uni-Lab OS 页面，执行只读检查或安全测试动作。

顺序可以由设备包的启动脚本自动完成，但脚本仍应输出每个组件的状态。不要仅凭网页能打开就判断协议链路正常。

## 启动图 配置规则

```json
{
  "id": "plc_gateway_01",
  "class": "community.example_lab.plc_gateway",
  "config": {
    "endpoint": "opc.tcp://127.0.0.1:4855/example/",
    "namespace_uri": "urn:example:simulation",
    "connect_timeout_seconds": 10,
    "command_timeout_seconds": 60
  }
}
```

示例值仅用于解释字段。实际字段名和设备类从用户设备包检查报告取得，并遵守以下规则：

- HTTP 管理页面地址不能填入 OPC UA `endpoint`；
- 测试 启动图 与生产 启动图 分开保存，生产地址不得出现在模拟配置中；
- 优先使用 Namespace URI；只能使用 Index 时，必须确认服务重启后编号不会变化；
- 点位名称、数据类型和读写方向必须与点位表一致；
- 连接超时与动作超时分开设置，单位写清楚；
- 账号、私钥和证书密码通过受控配置注入，不写入 启动图。

## 三层就绪检查

| 层级 | 要看什么 | 通过标准 |
| --- | --- | --- |
| 进程层 | 仿真器和可选握手代理 | 进程运行，日志没有持续重启 |
| 协议层 | OPC UA Server | Endpoint 可连接，命名空间和关键点位存在 |
| 系统层 | Uni-Lab OS | PLC 设备在线，订阅和写入没有类型错误 |

若仿真器提供 Web 页面，页面只用于观察和受控测试。共享环境中不要修改点位、切换场景或停止服务。

## 最小联调步骤

1. 读取一个只读状态点，核对类型和值。
2. 在无硬件副作用的前提下写入测试命令。
3. 观察“命令已接收 → 执行中 → 完成”的状态变化。
4. 复位命令并确认状态返回空闲。
5. 分别模拟拒绝、超时和故障，确认工作流明确失败且不会自动重复危险动作。
6. 重启仿真器，确认 Uni-Lab OS 能按设备包规定的策略恢复连接。

## 切换到真实 PLC

切换前复制并锁定一份生产 启动图，由现场负责人填写真实 Endpoint、证书和点位配置。先完成只读连接，再进行单动作低风险测试，最后才执行完整工作流。仿真器中通过的结果只证明软件合同基本一致；急停、互锁、限位、人员防护和异常恢复仍必须由现场安全验收确认。

## 常见问题

| 现象 | 检查重点 |
| --- | --- |
| 页面可用但设备离线 | OPC UA Server 是否启动、启动图 是否使用协议地址、Uni-Lab OS 是否已建立设备连接 |
| BadNodeIdUnknown | 点位名称或命名空间不一致 |
| 写入类型错误 | 启动图 参数类型与点位表数据类型不一致 |
| 动作一直运行 | 完成/复位点没有按握手规则变化，或动作超时配置过长 |
| 任务重复产生动作 | 超时后未经现场确认就重新提交；先查询原命令状态 |

完成仿真联调后，按[系统安装](installation.md)保存设备包版本、启动图 和测试结果。
