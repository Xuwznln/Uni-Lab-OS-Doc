# 能力检查表

:::{admonition} 阅读角色
- **业务负责人**：确认需要交付和允许使用的能力范围。
- **开发或运维人员**：提供定义、加载、连接和联调证据。
- **验收人员**：依据检查表判定能力是否达到正式使用条件。
:::

通用产品能力统一见[认识 Uni-Lab OS](overview.md)。本页不再重复功能介绍，只用于区分“代码中有定义”“当前环境已加载”和“现场已经验收”这三个层级，帮助业务人员判断一项能力现在能否使用。

## 设备包能力核对

| 层级 | 需要的证据 | 结论 |
| --- | --- | --- |
| 已定义 | 设备包源码和静态检查通过 | 只能说明定义存在 |
| 已加载 | `package inspect` 和 Workspace 状态可找到对象 | 可以开始隔离测试 |
| 已连接 | Uni-Lab OS 报告设备在线并能读取状态 | 不等于动作已安全验收 |
| 已联调 | 单动作与失败路径测试通过 | 可以进入多设备联调 |
| 已验收 | 正式启动图（Graph JSON）、物料和安全流程通过审批 | 才能按批准范围生产使用 |

## 每类设备必须说明的边界

| 设备能力 | 必须写清楚 |
| --- | --- |
| 图像采集或检测 | 返回的是触发结果、文件路径还是算法结论；文件是否真实存在 |
| 加液、投料或移液 | 参数是目标值还是实测值；单位、精度和容差 |
| 搬运和开合盖 | 库位、容器状态、互锁和未知结果如何恢复 |
| PLC/网络设备 | Endpoint、认证、点位或接口版本、超时和幂等规则 |
| 串口设备 | 端口、波特率、帧格式、结束符和断线恢复 |
| 上位机或鼠标自动化 | 软件版本、窗口状态、成功证据和人工接管办法 |

## 使用原则

只有“定义、加载、连接、联调、验收”都满足，才能将能力标记为本环境可直接使用。设备包升级、启动图 变化或现场设备固件变化后，受影响的层级必须重新验证。
