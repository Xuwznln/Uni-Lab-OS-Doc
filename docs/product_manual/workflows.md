# 工作流发布与任务运行

:::{admonition} 阅读角色
- **业务负责人**：确认实验目的、输入输出、参数单位、成功标准和失败处理。
- **开发人员**：编写或编排节点、物料流、控制结构、设备绑定和正式合同。
- **验收人员**：执行静态检查、预检、模拟运行、异常路径和受控真机验收。
:::

工作流面向一次完整实验目标。用户从已发布修订准备输入，先执行零写入预检，再创建普通或单步任务。

本页解释已经进入产品目录的工作流怎样发布、预检和运行。第一次创作应先完成[工作流基础](workflow-concepts.md)、[用户设备包 手写教程](first-workflow.md)和[编排特性](workflow-features.md)，之后日常创作推荐使用[AI 辅助方式](ai-workflow-authoring.md)。

开始实际运行前，还应准备[物料](materials.md)与[试剂](reagents.md)，发布被引用的[实验操作（子工作流）](experiment-operations.md)，并理解[运行模式、安全与恢复](runtime-safety.md)。

## 两种创作入口

- **AI 辅助创作（推荐）**：AI 先读取当前 Catalog、驱动、资源与 用户设备包 已跟踪流程，生成静态 Python DSL 草稿；人审查后通过“导入 Python”创建，再检查、发布和运行。
- **人工创作**：作者直接编写静态 Python DSL，适合学习最小语法、修复诊断和审查 AI 结果。
- **可复用实验操作**：在“实验室操作”画布创建或导入 `experiment_operation`，发布后插入上层流程。

当前“新建工作流”按钮只是入口占位，不能从空白画布创建普通工作流；Uni-Lab OS 页面也没有通用的一键 AI 生成入口。AI 的推荐接入方式与安全边界见[用 AI 编写工作流](ai-workflow-authoring.md)，完整语法和约束见[工作流编排特性](workflow-features.md)。

## 查找和理解工作流

进入“工作流”页后：

1. 按名称或关键词搜索。
2. 打开详情，查看类型、当前修订和发布状态。
3. 在“拓扑”中查看节点和依赖。
4. 在“合同”中查看公开输入、输出和资源要求。
5. 在“诊断”中处理定义错误或未绑定项。
6. 在“源码”中只读查看或复制定义。

工作流可以从 Python 或 JSON 导入。Python 文件只进入静态 AST 编译器，不会作为普通程序执行；导入用于创建新身份，不覆盖已经存在的工作流 UUID。

## 发布修订

当 Runtime 的 `can_run_unpublished` 能力关闭时，只运行已发布内容。发布前应确认：

- 节点与连线完整；
- 每个设备动作绑定到有效实例；
- 必填参数有来源；
- 输入输出类型兼容；
- 子工作流引用已发布合同；
- 材料来源和站点选择不冲突。

发布当前修订形成不可变的发布合同。已经创建的任务持有自己的冻结执行图和源码快照，之后编辑或发布新修订不会改变它。

## 准备一次运行

打开“运行准备”，完成以下内容：

1. 选择已发布修订。
2. 填写公开输入。
3. 为每个 `ResourceSlot` 选择具体物料或来源站点。
4. 如果工作流暴露站点参数，保证同类来源没有选择同一占用位。
5. 选择运行方式：普通或单步。
6. 选择普通/高优先级并填写描述。
7. 核对页面推导出的材料依赖和试剂数量要求。

优先级只影响可调度节点之间的选择，不会绕过设备锁、工位锁、库存预留或安全条件。

## 运行前检查

预检可能给出三类结果：

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| `runnable_now` | 当前快照下满足运行条件。 | 可以提交；提交时仍会复检。 |
| `temporarily_unavailable` | 定义有效，但设备、资源或库存暂时不可用。 | 查看阻塞明细，处理后重检。 |
| `invalid` | 输入、定义、绑定或资源合同不成立。 | 修正配置或重新发布。 |

预检是零写入操作：不会创建 Task、Job、执行锁或库存预留。任务提交会重新检查并原子地建立需要的运行状态，因此“刚才预检通过”不保证此刻一定立即运行。

## 普通运行与单步运行

- **普通运行**按依赖和资源条件持续调度，适合已验证流程。
- **单步运行**创建标准 step Task，初始或切换后由操作员选择下一个可执行节点；提交前要求没有其他活动任务且没有待完成的任务清理，适合受控的单步验证。

旧的 `/api/v1/debug/*` 断点调试接口已经固定返回 HTTP 410。不要使用旧 CLI、MCP 或 Workbench 中仍指向该接口的“debug launch/breakpoint”；当前正确路径是标准 step Task。

## 组合工作流

工作流可以引用已发布实验操作。调度器在运行计划中原子展开组合调用，同时保留合同 UUID/digest、参数、设备绑定和物料依赖。不要依赖“子操作最近发布的合同”这种隐式行为；每次修改后应重新检查并发布上层工作流。

## 提交后的去向

创建成功后转到“任务”页。任务会经历等待资源、运行、暂停、需要人工处理、成功、失败或取消等状态。继续按[任务运行、并行调度与异常处理](tasks.md)查看节点、理解等待、处理人工确认并核对结果。
